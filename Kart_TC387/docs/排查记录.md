## 1. 【已定位】转向绝对值编码器读不出 —— MOSI 错布到 P23.1

### 结论
第一版和第二版 PCB 都把转向角传感器的 **MOSI 布到了 P23.1**，而 **P23.1 在 TC264/TC387 任何一颗芯片上都不是合法的硬件 SPI MOSI 引脚**。

### 证据链
- 网表事实（v1 与 v2 相同）：
  ```
  转向角传感.1 → P22.0     转向角传感.2 → P23.1
  转向角传感.3 → P22.1     转向角传感.4 → P22.3
  转向角传感.5 → VCC3V3    转向角传感.6 → GND
  ```
- 2x3 排针为**反序映射**（焊盘 N ↔ 模块线 7−N），由电源脚 .5=VCC/.6=GND 反推 + 编码器 A/B 落点验证确认。
- 模块线序：1=GND 2=VCC 3=SCLK 4=MISO 5=MOSI 6=CS。
- 反序映射后实际落点：
  | 模块信号 | 落到 MCU | 代码配置 | 一致 |
  |---|---|---|---|
  | SCLK | P22.3 | P22.3 | ✓ |
  | MISO | P22.1 | P22.1 | ✓ |
  | **MOSI** | **P23.1** | P22.0 | ✗ |
  | **CS**   | **P22.0** | P23.1 | ✗ |
- 用户已查原理图确认：MOSI 确实落在 P23.1。
- 库枚举佐证：TC387 SPI4 MOSI 合法脚仅 P22.3 / P22.0 / P33.12；P23.1 不在其中。这颗磁编自检需靠 MOSI 写配置寄存器，MOSI 不通 → 自检失败、读回垃圾。

### 处理
- **第一版**：飞线解决（用户已决定）。把模块 MOSI 引到 P22.0、CS 引到 P23.1，与代码 `board_pins.h` 一致。
- **第二版**：定版前把转向角传感器接口 `.1`/`.2` 两焊盘对调，即可省掉飞线。（用户已确认会改 v2）

### 代码侧（无需改，已正确）
`board_pins.h` 当前配置本身与"期望接线"一致：
```c
#define KART_STEER_ABS_SPI_INDEX     (SPI_4)
#define KART_STEER_ABS_SPI_SCK_PIN   (SPI4_SCLK_P22_3)
#define KART_STEER_ABS_SPI_MOSI_PIN  (SPI4_MOSI_P22_0)
#define KART_STEER_ABS_SPI_MISO_PIN  (SPI4_MISO_P22_1)
#define KART_STEER_ABS_SPI_HW_CS_PIN (SPI_CS_NULL)
#define KART_STEER_ABS_CS_GPIO_PIN   (P23_1)
```
另注：`kart_steer_abs.c` 的读取协议是逐飞官方 `zf_device_absolute_encoder.c` 的忠实移植，协议无误。
（备选：若飞线不便，可改用逐飞官方软件 SPI，`ABSOLUTE_ENCODER_USE_SOFT_SPI=1`，任意 GPIO 可当 MOSI/CS，按实际接线配置即可。）

## 2. 【待验证】右后编码器完全没数 —— 大概率硬件

### 现象
右后编码器（P10.3/P10.1，TIM5）完全读不到数（`r_raw` 恒 0）。左后（P33.7/P33.6，TIM2）正常。

### 已排除
- **软件链正常**：`kart_debug_uart_poll()` 内已调 `kart_encoder_update()`，`r_raw` 会刷新。
- **代码正常**：`kart_encoder.c` 左右完全对称，`board_pins.h` 枚举正确。
- **接线映射正常**：网表 A→P10.3(CH1)、B→P10.1(CH2)，与左后对称。

### 关键库差异（TIM5 与 TIM2 本质不同）
查 `zf_driver_encoder.c`：
| | 左后 TIM2 | 右后 TIM5 |
|---|---|---|
| 归属 | GPT2 块 | GPT1 块 |
| 模式 | incrementalInterface 真正交 | counter 计数器 |
| 倍频 | 双边沿双通道 4 倍频（读数÷4）| 仅 TxIN 上升沿 1 倍频（不÷4）|
| 方向 | A/B 正交解码 | B 相电平判方向 |
- 库设计使两侧最终标度一致（速度环不会失配）。
- 但 TIM5 方向判断天生比真正交弱，低速易抖 → 这也是 `KART_RIGHT_ENCODER_SIGN` 被设为 -1 的背景。
- 关键判断：TIM5 模式弱顶多导致方向乱跳，**不会"完全没数"**。完全没数 → 指向硬件。

### 决定性实验（不改代码，CSV 里已有工具）
CSV 字段 `r_ab` 由 `gpio_get_level` 直接读 P10.3/P10.1 电平（A=bit0, B=bit1, 值 0~3），与 TIM5 计数是独立通路。
**架起右后轮、断电机、手动匀速转，看无线 CSV：**
- 情况①：`r_ab` 在 0/1/2/3 跳变，但 `r_raw` 恒 0 → 信号到脚但 TIM5 没计数 → TIM5 配置问题，此时换/重配 TIM5 才有意义。
- 情况②：`r_ab` 恒定不动 → 信号没到脚 → **纯硬件**：接线/焊接/编码器供电/接触/虚焊。

### 关于"换掉 TIM5"
在 v1 现有硬件上**换不了**：
- P10.3/P10.1 在 TC387 库里只归 TIM5，无第二定时器可选这两脚。
- TIM3(P02.6/02.7) 被右后电机 DIR/PWM 占用；TIM4(P02.8) v1 未引出到编码器排针；TIM2 被左后占用。
- 换 TIM 等于飞线改接线，成本高于先查焊接。
**结论：先按上面实验区分硬件/软件，别急着换 TIM5。**

## 4. 库差异备忘：TC264 库 vs TC387 库（核心板切换关键）

| 项 | TC264 库 | TC387 库 |
|---|---|---|
| SPI 模块 | 仅 SPI_0~SPI_3 | SPI_0~SPI_4 |
| P22.0/22.1/22.3 归属 | SPI3 | **SPI4** |
| P23.1 硬件 CS | 支持(SPI3_CS13_P23_1) | 不支持 |
| 编码器枚举 | TIM2/TIM5 同 TC387 | 相同 |

隐患：代码写 `SPI_4` 必须链接 TC387 库；若误链 TC264 库则 `SPI_4` 不存在、编译不过。当前工程已确认链接 TC387 库。
