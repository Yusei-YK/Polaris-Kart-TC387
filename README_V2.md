## 1. 为什么要写 V2

旧 `README.md`（1513 行）是项目**早期 TC264 规划阶段**的产物，记录了当时较完整的方案设想，价值仍在。但随着主线换代，它与当前实际工程已产生几处差异，容易让后来者困惑：

1. **工程名不同**：旧文档围绕 `Seekfree_TC264_demo_6.3/`，当前实际主力工程为 `Kart_TC387/`（TC387 核心板）。
2. **模块多为设想**：旧文档列出的一批"计划新增"模块（`sensor_manager`、`imu_manager`、`heading_fusion`、`waypoint_nav`、`sensor_fusion_manager` 等）目前仍停留在规划阶段，尚未落地。
3. **技术主线换代**：旧文档主线是"GNSS 打点 + 卡尔曼融合航向"架构；当前实际方案改为**从 TopSpeed 极速越野工程迁移**成熟底层，走"编码器累计路程 + IMU yaw + 前轮角度闭环 + 左右后轮速度闭环 + Mission 状态机"的惯导轨迹复刻路线。

旧 README 作为历史规划保留归档，本文件描述当前真实现状。

## 3. 本轮做出的删改与考量

> 说明：以下为版本库客观现状盘点与整改，均针对既有内容做规整，不涉及对历史提交的评价，也不改写任何历史提交。

### 3.1 新增 `.gitignore`（此前仓库缺少）
仓库此前**没有 `.gitignore`**，一些本不适合入库的文件随工程目录一并进入了版本库：
- `6.6_V1_TC264/Debug/` 下 **534 个编译产物**（`.o/.elf/.hex/.map/.src/.d/.opt` 等）随整个工程目录一起被跟踪。
- 28MB 的 `6.6_V1_TC264.rar` 备份压缩包位于仓库根目录。

`.gitignore` 现已排除：编译产物（`Debug/`、`*.o/*.elf/*.hex/*.map` 等）、IDE 缓存（`.ads/`、`.metadata/`、`Configurations/`、`*.launch`）、压缩包（`*.rar/*.zip/*.7z`）。

**保留**：`libraries/` 下逐飞库源码（编译必需，不擅自删）。

### 3.2 从索引移除已跟踪的编译产物
用 `git rm --cached` 把已入库的 534 个 `Debug/` 产物移出 git 索引（**只清索引，不删本地文件，可逆**），使仓库回归"只跟踪源码"的干净状态。历史提交保持原样，可追溯来源。

### 3.3 纳入当前主力工程 `Kart_TC387/`
此前整个 `Kart_TC387/` 工程**尚未被 git 跟踪**——即当前实际开发的代码还未进入版本库。本轮将其源码（`user/`、`code/`、`docs/`、工程配置）纳入跟踪，编译产物按 `.gitignore` 排除。

### 3.4 文档换代
- 旧 `README.md`：保留归档，不删（保留历史规划思路）。
- 新增 `README_V2.md`（本文件）+ `docs/开发日志.md`：描述真实现状。

### 3.5 提交身份
本机 git 全局与本地 `user.name`/`user.email` 均为空，本轮整理提交以 `Yusei-YK <sojawike15@gmail.com>` 身份完成（通过 per-command 指定，未改动全局配置）。

## 4. 当前工程技术主线（Kart_TC387）

- **迁移来源**：TopSpeed 极速越野 TC377 工程（分层架构 + 优先级写同步 Power 模型 + Subject 状态机）。
- **迁移原则**：保留 TopSpeed 架构/算法/比赛逻辑，只替换硬件相关底层。
- **科目一方案**：惯导轨迹复刻 = 编码器累计路程 + IMU yaw + 前轮角度闭环 + 左右后轮速度闭环 + Mission 状态机。
- **硬件现状**：第一版 TC264 通用主板 + TC387 核心板；第二版主板已出网表，未冻结。

详细底层排查结论见 `Kart_TC387/docs/排查记录.md`，开发过程见 `docs/开发日志.md`。
