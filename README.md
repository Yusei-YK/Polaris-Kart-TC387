## 仓库入口

本仓库当前主线是 `Kart_TC387/`：TopSpeed TC377 极速越野工程向 TC387 卡丁快跑科目一的移植。当前代码目标不是继续维护旧 TC264 模板，而是在 TC387 核心板上跑通低速、可停、可观测的底盘闭环平台。

当前控制主线：

```text
编码器累计路程 + IMU yaw + 前轮角度闭环 + 左右后轮速度闭环 + Mission 状态机
```

## 旧规划中保留的有效内容

旧 README 不是整篇废弃。它里面关于比赛任务、非阻塞状态机、安全停机、传感器分工、调试日志和分阶段开发的内容仍然有用；但旧文档绑定的是 TC264/Seekfree 模板和 GNSS/RTK 优先路线，工程落点已经不再适用。本 README 已把可保留部分按当前 `Kart_TC387/` 事实重写。

### 总体约束

1. 不使用摄像头视觉作为主闭环控制输入。
2. 主控制流程必须非阻塞，不能靠长时间 `delay` 推比赛流程。
3. 硬件底层 API 必须经应用层封装，业务代码不直接散落调用 PWM/GPIO/SPI/UART。
4. 不使用 `malloc`，不引入操作系统。
5. 出现急停、距离过近、路线段超时、关键传感器异常或驱动异常时，必须立即停车并进入故障状态。
6. 所有闭环调试必须有日志或 VOFA 通道支撑，不能靠肉眼和手感猜参数。

### 科目一：自动驾驶

当前目标是低速稳定完成卡丁科目一，优先用惯导轨迹复刻而不是 GNSS 完赛：

- 编码器累计路程用于距离推进和路径索引。
- IMU yaw 用于航向误差。
- 前轮绝对编码器用于转向角反馈。
- 左右后轮编码器用于速度闭环。
- TOF/GNSS 可作为后续辅助，不作为当前底盘调通前置条件。

倒车入库、绕桩、停车等流程应拆成状态机，例如：等待开始、发车、路径回放、减速、倒车对正、倒库、停车、故障。状态切换尽量依赖距离、yaw、角度、事件和故障标志，少用固定时间硬等。

### 科目二：人车交互

旧 README 中列出的灯光、蜂鸣器、雨刷和动作命令仍可作为后续需求来源，例如：

- 灯光：左转、右转、远近光、雾灯、双闪、车内灯。
- 蜂鸣器：1 秒、2 秒、3 秒、连续多次、报警。
- 动作：前进固定距离、后退固定距离、蛇形、左右 90 度、顺/逆时针绕圈。

当前已按 2026-07-03 更新的细则写完科目二高层命令枚举和 8 条任务状态机，但语音、蜂鸣器、门洞/动作路径和灯板扫描底层尚未完成，仍不能视为科目二可运行。

### 科目三：路径记录与返回

旧 README 中“不要简单倒放 PWM”的判断保留。当前更适合的路径点最小结构是：

```c
typedef struct {
    float distance_m;
    float yaw_deg;
    float speed_mps;
    uint8_t event;
} kart_path_point_t;
```

路径返回应根据编码器距离误差和 yaw 误差生成目标速度/目标转向，不按时间盲放输出。GNSS/RTK 可作为低频修正接口，不能替代室内低速阶段的编码器和 IMU 验证。

### 传感器和外设分工

| 模块 | 当前定位 |
|---|---|
| 左右后轮编码器 | 距离累计、速度反馈、路径索引 |
| 前轮绝对编码器 | 转向角闭环反馈，当前硬件关键 |
| IMU963RA | yaw reset、短时航向积分、转弯判断 |
| 无线/调试串口 | VOFA、在线调参、日志、模式切换 |
| 屏幕/按键 | 菜单和测试模式，不能阻塞高频控制 |
| TOF | 后续防撞/倒库距离辅助 |
| GNSS/RTK | 后续低频位置修正或备份模式 |
| 语音/灯光/雨刷 | 科目二扩展，需按正式规则再核 |

### 软件结构规划

当前 `Kart_TC387/user/` 采用平铺文件结构，用 `kart_` 前缀表达模块边界：

- `kart_power`：统一动力输出、限幅、停机、遥控接管。
- `kart_encoder`：左右后轮编码器读取。
- `kart_steer_abs`：前轮绝对编码器读取。
- `kart_imu`：IMU 初始化、标定、yaw 更新。
- `kart_pid`：PID 算子。
- `kart_control`：当前后轮平均速度环，后续拆左右轮独立环。
- `kart_debug_uart`：VOFA 和在线改参。
- `kart_light`：科目二 8 种灯光命令的 7x15 点阵逻辑、亮度和非阻塞动画；逻辑测试已覆盖全部图案与动画，TLD7002 硬件扫描层待接入。
- `kart_mission`：三科目高层状态机、科目二 8 条任务流程、底层就绪门控和安全停机请求。
- `kart_mission_ui`：IPS200 任务/实时状态页与旋钮按键事件接口；实体按键驱动待接入。
- 后续再补：`kart_path`、转向角环、yaw 外环、语音/蜂鸣器底层和参数保存。

总体数据流保留旧规划的分层思想：

```text
传感器原始数据
  -> 应用层封装
  -> 底盘状态估计
  -> Mission/Subject 状态机
  -> 目标速度/目标前轮角
  -> PID 闭环
  -> kart_power 统一输出
  -> 三路 DIR+PWM
```

### 后续开发阶段

1. 编译和上电自检：启动稳定，所有电机默认停止。
2. 传感器验证：编码器、转向 raw、IMU yaw 都能稳定观察。
3. 执行器开环：三路电机悬空、低 PWM、单路正反测试。
4. 停机链路：`e0`、遥控/软件 disable、异常停机必须可靠。
5. 后轮速度闭环：先单环，再拆左右独立环。
6. 前轮角度闭环：修好硬件后再开，不允许打死。
7. yaw 外环：yaw 误差生成目标前轮角。
8. 路径记录与回放：先悬空，再低速地面。
9. 科目一联调：高层状态机已写，接入真实路径事件后再做短距离、低速、可随时断电的验证。

## 关键事实

- `Kart_TC387/user/board_pins.h` 是当前板级引脚事实来源。
- `kart_remote` 没有独立 `.c` 文件，实现写在 `Kart_TC387/user/kart_power.c` 里。
- `Kart_TC387/user/kart_steer_abs.c` 是转向绝对编码器 SPI4 板级适配；协议与逐飞设备驱动一致，底层调用逐飞 SPI/GPIO。逐飞设备层硬编码 SPI0，会与本车 IMU 冲突，因此不能直接套用。
- `Kart_TC387/user/cpu0_main.c` 主循环已周期调用 `kart_steer_abs_update()`，不是只在 init 读一次。
- `Kart_TC387/user/isr.c` 的 5ms 中断调用 IMU、速度环和只累计时间的 `kart_mission_tick()`；Mission 状态转换和屏幕刷新都留在主循环。
- `Kart_TC387/user/cpu0_main.c` 已接入 Mission、IPS200 和灯板请求，但运动请求尚未接到底盘控制器，因此状态机不会自行写 PWM。
- `examples/TLD7002_LED_Dot_Matrix/` 仅是逐飞官方参考例程；原理图已确认当前 PCB 必须使用 20 针转 24 针飞线，TLD7002 驱动尚未接入主工程。

## 安全禁忌

- 不确认电机方向、编码器方向、前轮角度读数前，不开闭环。
- 不确认停机链路前，不落地自动运行。
- `e0` 的软件路径已改为立即清零后轮请求并通过主机测试；此前实车“不停”现象尚未悬空复测，复测通过前仍按安全故障处理。
- 转向硬件已有打死烧毁事故记录，修复硬件和限幅前不要做地面自动测试。
