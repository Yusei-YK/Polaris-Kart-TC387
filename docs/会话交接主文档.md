## 3. 运行架构与调用顺序

### 3.1 核心职责

| 核心 | 职责 | 关键文件 |
|---|---|---|
| CPU0 | **当前承担全部功能**：上电初始化、安全功率控制、速度环、转向内/外环、IMU、里程计、录制、复现、任务状态机、菜单、遥控轮询、点阵屏扫描、日志、调度器 | `cpu0_main.c`、`isr.c` |
| CPU1 | 设计上跑 `kart_imu_update()`/`kart_odom_update()`；**邮箱关闭中，当前无负载** | `cpu1_main.c`、`kart_imu.c`、`kart_odom.c` |
| CPU2 | 设计上跑 `kart_record_poll()`；**当前只提供 `cpu2_dsram` 录制缓冲区，无负载** | `cpu2_main.c`、`kart_record.c` |
| CPU3 | **只跑 `kart_multicore_core3_service()`**（邮箱服务空转），不再跑点阵屏/菜单 | `cpu3_main.c` |

跨核调度在 `kart_multicore.c/.h`。共享邮箱位于 CPU0 DSRAM；IMU/里程计数据段挂 CPU1 DSRAM，录制缓存（含科目四 `kart_steer[]/dist[]`）挂 CPU2 DSRAM。**当前 `MULTICORE_COMPAT_ENABLE=0`**：`kart_multicore_imu_update/kart_odom_update/kart_record_poll` 都直接本地调用对应实现，CPU1/CPU2 RPC 未接管；置 1 才走同步邮箱搬到目标核（但同步 RPC 不等于并行收益，见 §2）。菜单与点阵屏都在 CPU0（菜单曾试搬 CPU3，因跨核 Flash/状态竞争已还原）。

### 3.2 关键时序（不得随意调整）

5 ms 中断 `CCU60_CH0`：

```text
pit_clear_flag(CCU60_CH0)
 → kart_debug_uart_tick_5ms()        日志 tick（只计数，不发送）
 → kart_multicore_imu_update()       IMU 姿态（邮箱关→本地 kart_imu_update）
 → kart_control_speed_update()       后轮速度环（单 PID 跑两轮均值）
 → kart_multicore_odom_update()      里程计（同上，本地执行）
 → 速度环未使能时 power_force_rear_pwm_zero()
 → g_tick_5ms++                 放在最末，主循环靠它对拍
```

CPU0 主循环（2026-07-24 改为 **5ms PIT tick 协作式调度器**，`USE_SCHEDULER=1`）：

```text
时基：cc60_pit_ch0_isr 每 5ms 末尾 g_tick_5ms++（硬件拍，不受主循环耗时影响）
主循环忙等 tick 变化，每变一拍分发一次；sched_count 分频出 10/50/100ms 拍。
  5ms 拍(每 tick, kart_task_5ms)：
      power_check_poll() → kart_steer_abs_update()（SPI 绝对编码器）
      → kart_playback_poll()（含开环倒回分支）→ kart_steer_ctrl_update()（串级）
      → 未使能则 power_set_rear_duty(0,0) → power_sync()（slew 限幅统一下发）
  10ms 拍(kart_task_10ms)：kart_remote_poll(10) → kart_mission_poll()
      → kart_multicore_record_poll() → kart_debug_uart_poll()（采样组帧入环形缓冲）
  50ms 拍：kart_menu_poll()（按键扫描 + IPS200 刷新）
  100ms 拍：kart_dot_show_mode()（点阵显模式号字符串）
空转：tick 未变时反复 kart_debug_uart_background_poll() 非阻塞排空日志环形缓冲。
漏拍：一次跨 >1 tick 累加 g_sched_overrun_count，只跑最新拍不补跑。
注：**点阵屏逐 entry 扫描不在主循环**，由 SYNC 下降沿的 EXTI 中断触发（见 §8）。
```

- 旧主循环（末尾 `system_delay_ms(5)`，周期非恒定）保留在 `#else` 分支，置 `USE_SCHEDULER=0` 可 A/B 对照回退。
- 调度器运行时监测：`g_sched_last_exec_us`（上拍分发耗时）、`g_sched_max_exec_us`（历史最大，应 <5000）、`g_sched_overrun_count`（漏拍累计，稳态应为 0），均上 VOFA CH25~27。

初始化顺序（`cpu0_main.c`）：时钟/调试/kart_multicore → 功率/编码器/转向绝对编码器/日志串口/控制器/转向串级 → **点阵屏 init（亮度 10000）+ 全亮"标定中"指示** → `kart_imu_init()` 静止标定 → 撤全亮 → `kart_odom_init()` → `pit_ms_init(CCU60_CH0, 5)` 开 5 ms 拍 → `/* kart_voice_init(); */`（**已注释，UART1 冲突**，`cpu0_main.c:196`）→ 蜂鸣器/运动/录制/复现 → 任务 → 遥控 → 菜单 → `cpu_wait_event_ready()` 四核屏障 → `kart_multicore_enable_runtime()`。

## 4. 操作与安全边界

### 4.1 菜单和按键

- 按键：UP `P33_11`，DOWN `P20_6`，MID `P20_7`，LEFT `P33_4`，RIGHT `P21_7`。
- 主菜单提供 **Subject 1、Subject 2、Subject 4**；Subject 2 下含 Voice Control 与 Gate Recording（Record / Playback / Back）；Subject 4 直接进 `MENU_LEVEL_S4_RUN` 运行页。
- MID 同时用于确认、开始录制、结束录制；`P20_7` 也是 START 键。**`MENU_LEVEL_S1_READY` 与 `MENU_LEVEL_S4_RUN` 两个界面不消费 MID**，把 `P20_7` 让给 kart_mission 当 START；修改任一处前必须联测这三条路径。
- `kart_playback_is_running()` 为真时 `kart_menu_poll()` 直接 return（复现中不响应菜单，避免误操作/屏幕重绘抢时间）；状态栏每拍重绘。
- 已知风险：`kart_menu_poll()` 在录制等待/录制状态有专门 MID 处理，后续又进入普通 MID 分发；该双重边沿处理暂未整改，不能在不复测菜单交互的情况下移动菜单到其他核心。
- **2026-07-24 曾试把菜单搬 CPU3**（`core3_main` 跑 `kart_menu_init/poll`），实测屏幕可亮、菜单可翻；但菜单按键动作会调 `kart_mission_set_mode()`、`kart_record_save_to_flash()`、`kart_playback_start()` 等，与 CPU0 控制链跨核竞争同一状态/Flash，隐患未解决，**已还原回 CPU0**（50ms 拍 `kart_menu_poll`）。若日后要搬 CPU3，须先加跨核请求机制（菜单把这些动作发 CPU0 执行，同 `multicore_*` 那套）。

### 4.2 遥控

- SBUS：UART3，100000 baud 8E2，25 字节帧；超时 `100 ms` 或失控位有效时判为离线。字节间隔 `>3000 us` 视作帧间空隙并重置接收长度（帧重同步）。
- 三段开关：L=急停并关闭转向角度环；M=仅转向；H=转向加速度控制。最大目标速度为 `±20` 脉冲/5 ms，死区为 `±60`。
- 标定基线：方向 中位 `968` / 左 `1768` / 右 `168`；油门 中位 `880` / 前 `579` / 后 `1180`；SW3 三档 `192/992/1792`；`REMOTE_STEER_SIGN=+1`。原始通道值可在 VOFA CH31（油门）/CH32（方向）直接看。
- **2026-07-26：sw3 改为每次 `kart_remote_poll()` 都解码**（不再只在遥控模式），并加去抖 `REMOTE_SW3_FILTER_COUNT=3`（同一挡位连续 3 次采样才切换）；判离线时强制钳成 `L`（最安全态）。这样任何模式下 deadman 读到的都是实时挡位。
- `kart_remote_control_update()` 只在 `MISSION_REMOTE` 与 `MISSION_SUBJECT_4` 的 PHASE1 中调用。
- 复现 deadman：遥控离线或 SW3=L 时，`kart_playback_poll()`（含开环倒回分支）**在函数开头立即停止复现**。
- **坑（已踩过）**：`kart_remote_control_stop()` 会把挡位状态复位成 L，在切复现前调用它会被 deadman 当成"低挡"立即杀掉复现。`subject4_loop()` 因此**故意不调**该函数。

### 4.3 停车原则

- 完整安全停机必须经 `kart_mission_set_mode()` 的统一停机路径；它会停止录制/复现、清目标、关闭速度环和转向环、静音蜂鸣器并清语音队列。
- `b0` 仅停止复现相关控制，不能替代完整停机。

## 5. 科目与功能状态

### 5.1 顶层模式

`MISSION_IDLE / SUBJECT_1 / SUBJECT_2 / SUBJECT_4 / REMOTE / FAULT`，定义于 `kart_mission.h`，切换由 `kart_mission_set_mode()` 统一处理（先 `mission_stop_all()` 再进新模式）。

- `IDLE`：安全待机。
- `SUBJECT_1`：路径复现至 A 点后直线倒车入库。
- `SUBJECT_2`：语音与蜂鸣器轮询 + `kart_motion_update()`；也用于 Gate Playback。
- `SUBJECT_4`：**迷宫遥控录制 + 开环原路倒回**（阶段机见 §5.4）。
- `REMOTE`：遥控接管。
- `FAULT`：故障锁止。

点阵模式号（`kart_dot_show_mode()`，100ms 拍）：IDLE=`000`、SUBJECT_1=`111`、SUBJECT_2=`222`、SUBJECT_4=`555`、REMOTE=`333`、FAULT=`FFF`。

`mission_stop_all()` 做的事：停 kart_playback、停 kart_record、`kart_motion_stop()`、速度目标清零并关速度环、关航向外环与转向内环、蜂鸣器静音、清语音队列。

### 5.2 科目一：路径复现与倒车入库

流程为：`S1_WAIT_START → S1_CONE_ROUTE → S1_GARAGE_APPROACH → S1_REVERSE_IN → S1_FINISHED`。

1. START（P20.7 下降沿）启动已加载的路径复现。
2. 复现到录制终点 A 后停车。
3. 等待车速稳定，记录里程基准，关闭航向外环，保持转向内环并将目标回中。
4. 直线倒车；里程达到 `1.05 m` 降速，达到 `1.40 m` 停车。

倒车不使用航向外环，避免前轮修正使车尾发散。场地规则中“锥桶随机摆放”由现场手推录制路径消化，不依赖视觉。车库约为深 2 m、宽 1.5 m；A 是录制轨迹终点。A→B 的额外摆正段尚未单独实现，如实车发现 A 点不能直接倒车，再单独增加状态而不是修改现有倒车段。

### 5.3 科目二：语音与门洞路径

语音入口（菜单 Voice Control）**2026-07-24 起会切 `MISSION_SUBJECT_2`**：由 `subject2_loop()` 每拍独占跑 `kart_voice_poll()`+`kart_voice_dispatch()`+`kart_motion_update()`，MID/LEFT 退出时切回 `MISSION_IDLE`（完整停机）。当前已接通蜂鸣器类（0x0C~0x14）、门洞前进类（0x15~0x19→gate kart_playback 槽位，2026-07-24 接入待实车）、运动类（0x1F~0x26，待实车）；门洞返回类（0x1A~0x1E）保留未实现，灯光类（0x04~0x0B）待灯板点亮后再接。

**语音运动控制（2026-07-23 已落地，待实车）：** `kart_voice_dispatch()` 复用为统一路由——蜂鸣器忙或运动忙时本拍不取新命令（串行排队）；0x0C~0x14 → `kart_horn_start()`，0x1F~0x26 → `kart_motion_start()`。新建 `kart_motion.c/.h` 只做状态机（相位 IDLE/FWD/BACK/SNAKE_FWD/SNAKE_BACK/CIRCLE/TURN_APPROACH/TURN_ROTATE），每拍设目标（转角/航向/速度）+ 使能，实际 PWM 仍由主循环控制环产生（与 kart_playback/kart_remote 同架构，5 ms 延迟）。关键点：

- 旋转全部用 yaw：绝对航向无法量 360°，故用 `get_relative_angle(prev, now)` 累加成展开累计 yaw，跨 ±180 正确，圈判 360°、转弯判 90°。
- 前行/左右转 approach 段用航向外环保向（`head_enable(1)+target_yaw`）；后退/倒退蛇形不用航向外环（倒车时正反馈发散），复用科目一倒库的内环锁中位 + 负速直倒（`angle_enable(1)+target_delta(0)`）。
- deadman 急停：遥控失联或 SW3=L 立即完整停机（与 kart_playback 一致）；`mission_stop_all()` 已加 `kart_motion_stop()`，切出科目二时复位 motion_phase。
- 参数先测小（`kart_motion.h` 宏集中）：速度统一 7；前行/后退/蛇形先测 3 m（现场规定 ≥5 m）；蛇形摆幅、转弯角先小后调。

**2026-07-24 修复①（运动控制裸奔，实车定因）：** 昨日实车现象——说前行/后退车一直走不停、蛇形不摆、遥控急停失效，但喇叭全好。grep 定因：`kart_motion_update()` 只在 `subject2_loop()` 调（`kart_mission.c:217`），而旧代码进 Voice Control **只切菜单界面没切 `MISSION_SUBJECT_2`**，`subject2_loop` 从不运行 → update 不跑。分层根因：`kart_motion_start()` 只拨速度环 enable+设目标，实际 PWM 由 5ms 中断的速度环独立产生（不管 kart_mission 模式），所以车会动；但判停/deadman/蛇形翻打角全在 update 里，无人调 → 裸奔。喇叭是 CCU60_CH1 独立中断，故不受影响。修复：Voice 入口切 `MISSION_SUBJECT_2`、退出切 `MISSION_IDLE`，并删掉 `kart_menu_poll` 里那份重复的 `kart_voice_poll/dispatch`（原临时补丁，会与 subject2_loop 双份分发抢队列），语音处理归 subject2_loop 独占（10ms 拍，比菜单 50ms 更跟手）。改 `kart_menu.c` 四处。

### 5.4 科目四：迷宫遥控录制 + 开环原路倒回（2026-07-26 新增）

**思路**：迷宫段几何窄、正向 Pure Pursuit 在倒车时会正反馈发散，故不做横向闭环，改为**按里程弧长反向索引、开环回放录制时的转角序列**。

阶段机 `subject4_stage_t`：`S4_PHASE1_RECORD → S4_PHASE2_REVERSE → S4_FINISHED`（异常进 `S4_FAULT`）。

```text
菜单 Subject 4 → kart_mission 切 MISSION_SUBJECT_4 + 菜单进 MENU_LEVEL_S4_RUN
  进入时：锁存 START 键当前电平（防误触发）、kart_odom_reset() + set_active(1)
         、kart_record_start()、kart_remote_control_stop()
PHASE1_RECORD：每拍 kart_remote_control_update()，人工遥控开进迷宫，全程录制
  按 START(P20.7 下降沿) → kart_record_stop() → kart_playback_start_openloop_reverse()
  （此处故意不调 kart_remote_control_stop()，否则假 L 挡会被 deadman 杀掉倒车）
PHASE2_REVERSE：kart_playback_poll_openloop() 每 5ms 跑；等 !is_running() → FINISHED
```

开环倒回算法（`kart_playback_poll_openloop()`）：

```text
d = kart_odom.dist - dist0            已倒行弧长（里程标量恒增）
s = total_dist - d               剩余待倒弧长
while(dist[k] > s) k--           游标从录制末尾向起点递减
喂 steer_ctrl_set_target_delta(kart_steer[k])   只开转向内环
速度恒定 PLAYBACK_OL_SPEED = -12
s <= PLAYBACK_OL_FINISH(0.10) → 停车
```

- 数据源：`kart_record` 与航点同帧并行采样的 `steer_buf[]`（`kart_steer_abs_get_center_delta()` 实测转角）+ `dist_buf[]`（相对起点弧长），经 `kart_record_get_steer/get_dist/get_total_dist` 读取。**这两条数组不落 Flash**，断电即失，只服务本次会话。
- deadman 与正向复现一致：离线或 SW3=L 立即停。
- 诊断：复用 VOFA CH20~23 输出 `d / s / k / target_delta`（正向复现时这四路是 cur/aim 坐标，看时注意当前模式）。
- **已知局限**：开环不修横向误差，误差随距离累积（转向零点漂移、轮胎打滑都会放大）。先短距离（几米）验证，再逐步加长；若偏差不可接受，下一步方向是给倒回段加航向 P 修正（同 §6 方案B）。

**2026-07-24 已定因已修：复现起点死锁（原“绕第三桩死循环”实为发车即卡）。** 实车 VOFA CSV（“录制 回到起点 复现卡住.csv”）实锤：发车后 `pbrun=1`、kart_mission=SUBJECT_1、stage 停在 CONE_ROUTE，但 **CH3 playback_index 恒 0、CH4 目标速度恒 0、CH20/21 诊断 cur.x/cur.y 恒 0**，非 deadman（CH2 在线=1、低挡=0）、非完成判定。根因 H0：`kart_playback_poll()` 把世界坐标投影到起点车体系（`cur.x=origin_cos*dx+origin_sin*dy` 等），发车瞬间 `kart_odom≈play_origin` → `dx=dy=0` → `cur=(0,0)` 恒不变；`find_nearest` 在起点附近永远返回录制第 0 点 → index 卡死；`target_v=0.5*(wp[0].v_left+wp[0].v_right)` 而起点录制速度≈0 → 目标速度 0 → 车不动 → 位置永不变 → 死锁。与桩号无关，是发车就卡（此前误判为“绕第三桩”）。修复（`kart_playback_start()`）：①`playback_index = (n>3)?3:0` 跳过起点静止段，给非零初速脱离原点；②发车瞬间 `playback_target_yaw=kart_imu_get_yaw()` 初始化外环目标，消除方向盘用残留值乱打一下。**未动 Pure Pursuit 主体**（find_nearest/find_lookahead/poll 跟踪逻辑）。诊断插桩（cur.x/cur.y/aim.x/aim.y 四快照+getter，上 VOFA CH20~23）保留。待实车验证：跳 3 点若起步前冲改小到 2，若仍卡说明起点静止点更多再加。

## 8. 蜂鸣器、显示、硬件说明

- 蜂鸣器使用 CCU60_CH1 的独立 1 ms 中断和 GPIO 软件翻转；精确定时不能依赖主循环。推导见 `kart_horn.h` 文件头注释。
- **点阵屏（2026-07-25 现状，取代旧"CPU3/UART0"表述）**：7×15 单色点阵，TLD7002-16ES 列驱动 + **卡丁车板独加的 74HC238 行译码器**（官方方案无此片，见官方 README）。由 **CPU0** 驱动，TLD7002 走 **UART1**（P11.12/P11.10，2M，半双工 TX 回环进 RX）。
  - **扫描方案（官方 SYNC/EXTI）**：TLD7002 每 PWM 周期在 SYNC（**P15.8=ERU_CH5**）吐下降沿 → `exti_ch1_ch5_isr`（isr.c）→ `dot_matrix_screen_scan()`。每帧 14 entry（7 行 ×2）：偶 entry 消隐(EN 低)+设行地址+下发列占空比（下个 PWM 周期才生效），奇 entry 占空比已生效→拉高 EN 点亮。`g_dot_sync_edges` 累计 SYNC 边沿，帧率=SYNC_Hz/14。
  - **行选通链**：A0/A1/A2 = P20.8/9/10（行号低三位），ROW_EN = P33.8（接 74HC238 的 E3，**高有效**）。行→地址：R0=000(Y0)…R6=110(Y6)。每行输出：Yx → 1k → S8050(NPN) → AO3401(PMOS 高边) → 行线(~8V)。
  - **故障定位（软件已排除，硬件待修）**：VOFA 证明软件发行号 0→6 完美循环；逐行静态测试(`dot_matrix_screen_test_rows_static`, `DOT_ROWS_TEST`)实测地址 0~6 点亮物理行 = **1,3,6,2,6,6,4** → 第6行被 2/4/5 三个地址点亮、**第5/7行全不亮** = 地址线断/虚焊(地址塌缩) + 部分行输出链坏。**下一步：万用表量 74HC238 的 A0/A1/A2 三脚，对 VOFA 数字 0~6 核电平，定位哪根地址线断**；再量 Y0~Y6 输出确认每地址仅一个 Y 变高。
  - **诊断开关（在 `cpu0_main.c`，测完必须归 0）**：`DOT_ROWS_TEST` 逐行静态（每行 held 1s、期间每 10ms 重发占空比防看门狗超时、切行往 VOFA 发行号）；`DOT_ROW0_TEST` 锁第 0 行常亮。当前均为 0。
  - **相关文件**：`zf_device_dot_matrix_screen.c/.h`（scan/init/test）、`isr.c/.h`（EXTI CH5 分支 + g_dot_sync_edges）、`cpu0_main.c`（100ms 拍显模式号 + 测试开关）。
- **UART1 冲突（待长期解决）**：TLD7002 占 UART1 → 语音无线模块（BOARD_WIRELESS，UART1，P33.12/13）无法共存，`kart_voice_init()` 已注释禁用。长期方案：把 TLD7002 飞线挪回空置的 UART0（P14.0/14.1），UART1 让回语音，再放开 `kart_voice_init()`。灯光类语音指令(0x04~0x0B)待灯板点亮 + 挪线后再接。
- IPS200 并口屏仍由 CPU0 菜单访问。
- IPS200 数据线 D0~D7 为 P11.9~P13.3，控制线 P15.0~P15.5；旋钮 P11.2/P11.3 不在硬件 timer 候选表，使用软件正交解码。TopSpeed 的 SPI 屏和硬件编码器逻辑不能直接搬用。
- `HW_TEST=1` 会进入硬件自测死循环；屏幕/旋钮/五向键确认后必须恢复为 0。

## 9. 串口日志（VOFA JustFloat，当前生效）

`kart_debug_uart_poll()` 由调度器 **10ms 拍**调用、当前生效。当前 `kart_debug_uart.c` 只做**串口日志输出**，没有 e0/e1 等 VOFA 命令接收（那套命令接口属历史版本，现代码不含，下表仅供追溯，实际不可用）。

输出格式：**VOFA JustFloat**，`LOG_CHANNELS = 33` 通道 float32 小端 + 帧尾 `00 00 80 7F`（帧长 136 B）；UART_10 / P13.0 TX / P13.1 RX / 460800 baud（**经无线模块，模块串口速率须同为 460800，PC 端也须 460800**）；50 Hz（`LOG_PERIOD_TICKS=4`，即 20 ms 一帧；5 ms ISR 只增 tick，`kart_debug_uart_poll()` 在 10ms 拍组帧写入 512 B 环形缓冲，主循环空转时 `kart_debug_uart_background_poll()` 每次最多排空 16 B，非阻塞；缓冲不足则整帧丢弃、不发半帧；不追发历史帧）。VOFA 连接需把协议设为 JustFloat、通道数设为 **33**，否则错列。2026-07-24 已实车验证刷新正常（28 通道基线；07-25 扩至 31、07-26 扩至 33，待实车复验）。
