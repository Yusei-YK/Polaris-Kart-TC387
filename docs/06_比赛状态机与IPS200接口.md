# 比赛状态机与 IPS200 接口

## 设计来源

- 比赛流程按 2026-07-03 更新的《第 21 届智能车竞赛卡丁快跑组比赛科目细则》整理。
- 软件结构参考 `NEUQ_TopSpeed_CrossCountry_TC377` 的 `Mission + Subject + Menu` 分层，核对提交为 `7361f0123e952c7875e250c86325f2bbe4d9b43b`。
- 只复用架构，不复用极速越野的赛道状态、控制参数和执行动作。

规则来源：<https://blog.csdn.net/zhuoqingjoking97298/article/details/154697989>

参考仓库：<https://github.com/RyanChenJH/NEUQ_TopSpeed_CrossCountry_TC377>

## 文件与职责

| 文件 | 职责 |
|---|---|
| `Kart_TC387/user/kart_mission.c/.h` | 三科目状态、合法转换、任务枚举、就绪门控、持续停机要求 |
| `Kart_TC387/user/kart_mission_ui.c/.h` | IPS200 任务页、实时数据页、旋钮/按键事件接口 |
| `Kart_TC387/user/isr.c` | 5ms 固定节拍只推进比赛计时，不切状态、不改动作请求 |
| `Kart_TC387/user/cpu0_main.c` | 检查运行中就绪位、应用灯板请求、消费停机要求、刷新 IPS200 |
| `tests/kart_mission_logic/` | 与硬件无关的状态转换测试 |

状态机不直接写 PWM。它只产生 `kart_mission_request_t`，后续路径规划、蜂鸣器和底盘控制器消费请求并在完成后回报事件。

## 三科目流程

### 科目一：自动驾驶

```text
WAIT_START
  -> LEAVE_START
  -> SLALOM
  -> APPROACH_GARAGE
  -> REVERSE_ALIGN
  -> REVERSE_PARK
  -> FINISHED
```

状态推进事件分别由路径索引、锥桶/区域识别、距离、yaw 和倒库控制器产生。当前没有使用固定时间自动跳转。

### 科目二：人车交互

规则说明每组口令包含四个区域共 8 条任务，但文字版没有直接给出分区配额。当前实现按场地往返顺序推定为：

```text
灯光 2 条
  -> 鸣笛 2 条
  -> 去程门洞 1 条
  -> 动作区动作 2 条
  -> 返程门洞 1 条
  -> 共 8 条完成
```

`2+2+1+2+1` 是当前默认口径，不是原文逐项写明的配额。拿到正式抽签任务表后必须复核；如口径不同，先修改 `KART_MISSION_S2_*_TASK_COUNT`，再同步调整状态机测试。

代码已经定义：

- 8 种灯光命令。
- 9 种鸣笛命令。规则文字写“八种”，但逐项实际列出 9 种，代码全部保留。
- 5 种去程门洞和 5 种返程门洞，并阻止在错误方向阶段提交门洞任务。
- 8 种动作区运动命令。

语音模块识别出命令后调用对应的 `kart_mission_submit_*()`；执行器完成后发送 `KART_MISSION_EVENT_TASK_DONE`。

### 科目三：路径记录与返回

```text
WAIT_RECORD
  -> RECORDING
  -> READY_RETURN
  -> RETURNING
  -> FINISHED
```

第一阶段的引导方式由底层决定。分赛区可按规则使用驾驶/遥控，国赛要求视觉跟随；两种方式最终都必须提供稳定的路径记录能力并置位 `KART_MISSION_READY_GUIDE_FOLLOW`。第二阶段必须按第一阶段记录的路径自动返回，不能简单倒放 PWM。

## 就绪门控

`kart_mission_arm()` 会检查当前科目的 `required_mask`。缺少任意能力时保持 `IDLE`，IPS200 显示十六进制 `MISSING` 位图；运行中丢失就绪位会进入 `FAULT` 并持续要求停机，直到人工复位回 `IDLE`。

当前代码不会自动把任何位设为就绪。只有底层完成且经过台架测试后，才允许调用：

```c
kart_mission_set_ready(KART_MISSION_READY_SPEED_CTRL, 1U);
```

主要位定义：

| 位 | 含义 |
|---|---|
| `SPEED_CTRL` | 后轮速度控制可靠 |
| `STEER_CTRL` | 前轮角度闭环和软限位可靠 |
| `YAW_CTRL` | yaw 外环可靠 |
| `SAFE_STOP` | 软件停机链路实测可靠 |
| `PATH_FOLLOW` | 路径跟踪器可靠 |
| `VOICE` | 科目二语音识别可靠 |
| `LIGHT` | 灯板硬件扫描可靠 |
| `HORN` | 无源扬声器波形执行可靠 |
| `PATH_RECORD` | 路径记录可靠 |
| `GUIDE_FOLLOW` | 科目三第一阶段引导可靠 |

因此当前实车默认无法启动比赛状态机，这是有意的安全限制，不是缺陷。

## IPS200 页面与按键接口

当前 v1 主板按 SPI2 屏初始化：`P15.3/P15.5/P15.1/P15.0/P15.2/P15.4`，方向为 320×240 横屏，100ms 局部刷新。

以上 API 和引脚已直接对照本仓库的 `Kart_TC387/libraries/zf_device/zf_device_ips200.h/.c`；ADS 工程的 `.cproject` 也已包含 `libraries/zf_common`、`zf_device`、`zf_driver` 和 `user` 目录。

任务页显示：选择科目、运行态、科目阶段、就绪/缺失位、科目二进度、用时、错误码和动作请求。实时页显示：yaw、转向 raw/delta、速度目标/反馈、duty、左右编码器累计和当前科目二任务。

输入驱动尚未绑定 GPIO。完成旋钮和按键消抖后，将硬件事件映射到：

```c
kart_mission_ui_event(KART_MISSION_UI_PREVIOUS);
kart_mission_ui_event(KART_MISSION_UI_NEXT);
kart_mission_ui_event(KART_MISSION_UI_ENTER);  /* 选择并尝试 ARM */
kart_mission_ui_event(KART_MISSION_UI_START);  /* 仅 ARMED 状态可启动 */
kart_mission_ui_event(KART_MISSION_UI_STOP);   /* 运行中立即 ABORT */
kart_mission_ui_event(KART_MISSION_UI_PAGE);   /* 切换任务/实时页 */
```

第二版 PCB 文档记录为 8 位并口屏，若实际使用第二版，不得直接沿用当前 `IPS200_TYPE_SPI`，需要先按实物修改屏幕初始化和引脚配置。

## 底层接入方式

后续控制器每周期读取请求：

```c
kart_mission_request_t request;
kart_mission_get_request(&request);
```

- `request.motion` 告诉路径规划当前应前进、倒车对正、倒库、通过门洞、执行动作、记录路径或自动返回。
- `request.light` 已在主循环接到 `kart_light_set_command()`。
- `request.horn/gate/motion_task` 分别交给后续蜂鸣器和路径动作执行器。
- 阶段完成时必须发送对应事件；异常调用 `kart_mission_fault()`，不能强行跳到下一状态。
