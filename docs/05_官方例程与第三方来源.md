### TC387 官方例程的接口事实

官方 TC387 Demo 当前给出的 TLD7002 通信配置为：

```text
UART_1
baud: 2,000,000
MCU TX: P33.12 -> 模块 RX
MCU RX: P33.13 <- 模块 HSLI_L
GPIN0: P32.4
SYNC: P20.9，ERU 下降沿中断
```

官方 7x15 点阵例程另使用 7 路行选：`P20.0`、`P20.3`、`P00.8`、`P33.9`、`P14.4`、`P14.5`、`P14.6`。

### 与当前 SmartCar 的差异

当前 `board_pins.h` 仍按旧硬件交接记录预留：

```text
P14.0 / P14.1: 灯板通信
P20.8 / P20.9 / P20.10: A0/A1/A2
P33.8: EN
```

这与官方 TC387 Demo 不同，因此不能直接复制官方引脚定义，也不能仅凭 P14.0/P14.1 就把灯板定为 UART0。后续接入前必须以实际 PCB 原理图和灯板接口为准，确认：

1. P14.0/P14.1 是否分别连接模块 RX 与 HSLI_L。
2. GPIN0 是否已经接到 MCU；当前 `board_pins.h` 未定义。
3. SYNC 是否已接到支持 ERU 的引脚；当前 P20.9 被标为行选 A1。
4. 当前 3 位行选加 EN 的外部译码结构，是否等价于官方 7 路直接行选。
5. UART0 默认调试串口与 P14.0/P14.1 的资源冲突。
6. 2 Mbps 串口、RX 中断和扫描中断对现有 5ms IMU/速度控制节拍的影响。

以上六项确认前，灯板保持“接口待核、驱动未集成”状态。
