# 硬件排查与第二版 PCB

本文档记录当前有效的硬件排查结论和第二版 PCB 注意事项。目标是保留硬结论，删掉重复会话说明。

## 项目硬件边界

- 当前工程：`Kart_TC387/`
- 当前核心板：TC387。
- 当前主板：第一版 TC264 通用主板 + TC387 核心板。
- 第二版主板：已有网表，未冻结。

## 致命问题：转向绝对编码器 MOSI/CS 错位

### 结论

第一版和第二版 PCB 都把转向角传感器的 MOSI 布到了 `P23.1`，但 `P23.1` 不是 TC387 合法 SPI4 MOSI 引脚。转向绝对编码器需要 MOSI 写配置寄存器，MOSI 不通会导致自检失败或读数异常。

当前代码期望接线：

```c
#define KART_STEER_ABS_SPI_INDEX        (SPI_4)
#define KART_STEER_ABS_SPI_SCK_PIN      (SPI4_SCLK_P22_3)
#define KART_STEER_ABS_SPI_MOSI_PIN     (SPI4_MOSI_P22_0)
#define KART_STEER_ABS_SPI_MISO_PIN     (SPI4_MISO_P22_1)
#define KART_STEER_ABS_SPI_HW_CS_PIN    (SPI_CS_NULL)
#define KART_STEER_ABS_CS_GPIO_PIN      (P23_1)
```

### 证据链

- 模块线序：1=GND，2=VCC，3=SCLK，4=MISO，5=MOSI，6=CS。
- 2x3 排针是反序映射。
- 反序后实际落点：

| 模块信号 | 实际 MCU | 当前代码 | 结果 |
|---|---|---|---|
| SCLK | P22.3 | P22.3 | 一致 |
| MISO | P22.1 | P22.1 | 一致 |
| MOSI | P23.1 | P22.0 | 错 |
| CS | P22.0 | P23.1 | 错 |

### 处理

- 第一版：飞线，把模块 MOSI 引到 `P22.0`，CS 引到 `P23.1`。
- 第二版：定版前交换转向角传感器座子 `.1/.2` 焊盘。
- 备选：改软件 SPI 兜底，但硬件修正优先。

## 待验证：右后编码器完全没数

现象：

- 左后编码器 `P33.7/P33.6`、TIM2 正常。
- 右后编码器 `P10.3/P10.1`、TIM5 读数恒 0。

已知事实：

- `kart_encoder.c` 左右读取逻辑对称。
- `board_pins.h` 中右后枚举为 `TIM5_ENCODER_CH1_P10_3` 和 `TIM5_ENCODER_CH2_P10_1`。
- TC387 库中 TIM5 与 TIM2 模式不同：TIM2 是真正交解码，TIM5 更像计数 + 方向电平判断。
- TIM5 模式弱可能导致低速方向抖，但不应导致完全没数。

下一步实验：

```text
架起右后轮，断电机，手动匀速转，观察 P10.3/P10.1 GPIO 电平或等效 r_ab 字段。
```

判断：

- GPIO 电平跳变但 `r_raw` 恒 0：信号到脚，TIM5 配置/库适配问题。
- GPIO 电平不跳：硬件问题，查接线、焊接、供电、编码器本体。

## 第二版已知变化

### 无线串口

第二版无线 UART 从 v1 的 UART2 改为 UART1：

```text
v1: P10.5 / P10.6
v2: P33.12 / P33.13
```

落板后需要改：

```c
BOARD_WIRELESS_UART_INDEX  -> UART_1
BOARD_WIRELESS_UART_TX_PIN -> UART1_TX_P33_12
BOARD_WIRELESS_UART_RX_PIN -> UART1_RX_P33_13
```

注意：`P33.12/P33.13` 与摄像头 UART1 资源冲突，已确认无线和摄像头不会同时用。

### 屏幕

第二版屏幕改 8 位并口。当前底盘代码未使用屏幕，不影响当前闭环调试。

### U1 核心板座

第二版封装仍标 `TC264_CoreBoard`，实际插 TC387 核心板。既有交接记录认为座子引脚兼容已核对，但落板后仍建议用电源、GND、关键 IO 再测一次。

### 电机驱动板动力电

第二版仍需确认驱动板动力电从哪里取。若缺少独立大电流端子，不能默认可以安全带载调试。

## 第二版按键规划

外置按键板总共 9 路交互信号：

| 信号 | 端口 | 说明 |
|---|---|---|
| ENC_A | P11.2 | 旋转编码器 A |
| ENC_B | P11.3 | 旋转编码器 B |
| ENC_SW | P20.6 | 旋转编码器按下 |
| UP | P33.11 | 五向上 |
| DOWN | P20.0 | 五向下 |
| LEFT | P21.6 | 五向左 |
| RIGHT | P21.7 | 五向右 |
| MID | P33.4 | 五向中 |
| START | P20.7 | 发车轻触 |

J_KEY 2x6 建议：

```text
1  GND         2  ENC_A
3  ENC_B       4  ENC_SW
5  UP          6  DOWN
7  LEFT        8  RIGHT
9  MID        10  START
11 VCC3V3     12  GND
```

编码器三路建议 `10kΩ + 100nF`；五向和 START 保持 `4.7kΩ` 上拉 + `470Ω` 串联。

## 安全硬件缺口

当前第一阶段没有补齐以下硬件能力：

- 后轮驱动 EN/nSLEEP。
- 后轮驱动 nFAULT。
- 三路电流采样。
- 独立硬件急停。

风险：

- 只有软件写 PWM=0，不等于硬件级关断。
- 堵转、短路、过温时软件可能无感知。
- 程序跑飞时软件急停可能失效。

当前取舍：用户已知第一阶段先靠软件限幅、短时测试和断电兜底。后续第二版仍建议补齐 EN/nSLEEP、nFAULT、电流采样和硬件急停。

## 当前事故与待查

- 转向上电打死导致单驱芯片烧穿，断电后转向电机电流倒灌回主板，炸主板电源二极管和 MOS 管。
- `e0` 关闭速度环后电机停不住，根因未定位。
- 双驱左后轮疑似烧毁：平均速度 I1 卡在 19~22，符合“左轮 0、右轮单独约 40、平均约 20”的假象。

## 调试前必做

1. 修复主板电源二极管/MOS 和烧毁驱动。
2. 查清 `e0` 停不住原因。
3. 三路电机全部悬空、低 PWM、单路测试。
4. 验证转向 raw 通道，不稳定不进角度环。
5. 验证右后编码器或单轮速度反馈，不要用平均值掩盖硬件故障。
