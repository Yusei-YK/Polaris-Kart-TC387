# 第二版主板检查清单

本文档从卡丁科目一代码需求反推第二版主板要检查的硬件接口。目标是避免软件写完后发现硬件缺关键反馈或安全信号。

## 1. 三路有刷电机接口

必须支持：

- 前轮转向电机。
- 左后轮驱动电机。
- 右后轮驱动电机。

每路建议至少包含：

```text
PWM
DIR
EN 或 nSLEEP
nFAULT
电流采样 ADC
GND
电源
```

风险：

- 只有 PWM/DIR 没有 EN/nSLEEP，软件无法可靠关闭驱动。
- 没有 nFAULT，驱动过流或保护时软件不知道。
- 没有电流采样，堵转时只能靠经验判断。

补救：

- 第一版若没有 EN/nFAULT/ADC，软件先保守限幅。
- 第二版必须补齐。

## 2. 第一版三路电机脚位

当前交接文档确认第一版：

```text
转向 DIR: P21_2
转向 PWM: ATOM0_CH1_P21_3

左后 DIR: P02_4
左后 PWM: ATOM0_CH5_P02_5

右后 DIR: P02_6
右后 PWM: ATOM0_CH7_P02_7
```

SmartCar `board_pins.h` 已经有相关 P21/P02 和 ATOM0 枚举，但命名是 `BOARD_MOTORx_PWMx`，第二版建议原理图和代码都改成更清晰的语义名。

## 3. 左右后轮正交编码器

第一版目标：

```text
左后: TIM2_ENCODER, P33_7 / P33_6
右后: TIM5_ENCODER, P10_3 / P10_1
```

风险：

当前 TC264 逐飞库里 `TIM5` 枚举和初始化分支存在，但 `encoder_quad_init()` 有断言限制 `encoder_n <= TIM4_ENCODER`。这会导致右后轮 TIM5 正交编码器存在编译或运行风险。

第二版建议：

- 优先把左右后轮编码器接到库明确支持正交的 TIM2/TIM3/TIM4 组合。
- 如果必须用 TIM5，先确认 `encoder_quad_init(TIM5...)` 在目标工程实际编译和运行不会触发断言。
- 不建议通过修改逐飞库来掩盖硬件选型问题。

## 4. 前轮角度绝对值编码器

第一版目标：

```text
SPI_3
SCK  P22_3
MOSI P22_0
MISO P22_1
CS   P23_1
```

SmartCar TC264 库中正确枚举是：

```text
SPI3_SCLK_P22_3
SPI3_MOSI_P22_0
SPI3_MISO_P22_1
SPI3_CS13_P23_1
```

风险：

- 不要使用 TC377 工程里的 SPI 枚举名。
- 不要直接用逐飞默认绝对值编码器配置，因为默认不是 SPI3/P23.1。

第二版建议：

- 保留 SPI3 四线。
- CS 同时保留硬件 CS 枚举和普通 GPIO 控制能力。
- 在线束上标清 3.3V、GND、SCK、MOSI、MISO、CS。

## 5. IMU

要求：

- IMU 固定在主板或车身刚性位置。
- 靠近主控，短线。
- 远离无线天线、大电流、电机线。
- 供电稳定。
- 最好使用 SPI。

当前 SmartCar 第一版：

```text
SPI_0
SCK  P20_11
MOSI P20_14
MISO P20_12
CS   P20_13
```

风险：

- IMU 排线太长会被无线和电机干扰。
- IMU 固定不牢会把震动当成姿态变化。

## 6. GPS UART

GPS 第一阶段不是主导航，但要保留备份接口。

当前第一版：

```text
UART3
TX P15_7
RX P15_6
```

检查：

- 是否有 GPS 供电。
- 天线安装是否远离遮挡和大电流。
- 是否有 PPS 或备用调试口，非必须。

风险：

- GPS 不应阻塞第一阶段室内调试。
- GPS 接口不要和屏幕、无线、摄像头冲突。

## 7. 无线调试 UART

当前第一版：

```text
UART2
TX P10_5
RX P10_6
```

第二版备选中提到：

```text
UART1
P33_12 / P33_13
```

风险：

- UART1 可能和摄像头或 ASCLIN 资源冲突。
- 无线天线可能干扰 IMU。

建议：

- 第一阶段优先保留 UART2。
- 第二版更换 UART 前必须查 ASCLIN 复用冲突。
- 无线模块和 IMU 保持距离。

## 8. 屏幕和按键

第一版屏幕使用 SPI。

检查：

- 屏幕 SCK/MOSI/MISO/CS/RST/DC/BLK 是否齐全。
- BLK 是否和 MISO 共脚，如果共脚要确认不会影响显示。
- 至少四个按键或五向按键。

卡丁第一阶段需要的菜单模式：

```text
MODE_SENSOR_TEST
MODE_STEER_TEST
MODE_WHEEL_TEST
MODE_REMOTE_DRIVE
MODE_PATH_RECORD
MODE_PATH_REPLAY
MODE_SUBJECT1_AUTO
MODE_FAULT_VIEW
```

## 9. 蜂鸣器

要求：

- 上电提示。
- 进入自动模式提示。
- 故障提示。
- 急停提示。

蜂鸣器不是必须控制车，但对调试安全很有用。

## 10. 急停输入

必须检查：

- 是否有独立急停输入。
- 默认态是否安全。
- 断线时应进入停机还是运行，建议断线停机。
- 是否有硬件下拉/上拉，避免悬空。

风险：

- 只有软件按钮，没有硬件急停，调试三路电机危险。

## 11. 遥控接管输入

要求：

- 能让人工接管或至少 disable 自动输出。
- 有超时保护。
- 断联后停机。

TopSpeed 的经验是遥控/无线不稳定时必须有超时锁死。卡丁第一版即使不做完整遥控，也应保留接管/disable 输入。

## 12. 电池电压采样

建议：

- VBAT 分压到 ADC。
- 标注分压比。
- 保护 ADC 输入不超压。

风险：

- 电池低压时闭环会变差。
- 电池电压过低继续运行会损坏电池或导致主控复位。

## 13. 电流采样

建议每路驱动有电流采样 ADC，至少左右后轮和转向各一路。

用途：

- 堵转保护。
- 转向顶到机械限位检测。
- 驱动异常诊断。

如果第一版缺失：

- 软件限制 PWM。
- 转向加软限位。
- 测试时缩短运行时间。

## 14. 5V 和 3.3V 测试点

必须有：

- 5V 测试点。
- 3.3V 测试点。
- GND 测试点。
- 电池输入测试点。

原因：

- 上电异常时第一步就是量电源。
- 传感器异常时能快速判断是供电还是通信问题。

## 15. 关键信号测试点

建议加测试点：

- 三路 PWM。
- 三路 DIR。
- 三路 EN/nSLEEP。
- 三路 nFAULT。
- 左右编码器 A/B。
- 绝对值编码器 SPI 四线和 CS。
- IMU SPI。
- GPS UART。
- 无线 UART。
- 急停输入。

## 16. 锁扣和线束

驱动板、电机、编码器、IMU、屏幕、无线都应使用可靠接口。

风险：

- 智能车调试中很多故障来自接触不良。
- 电机和编码器线束松动会导致闭环突然失控。

建议：

- 电机和电源接口使用锁扣。
- 编码器和 SPI 线束做防反插。
- 丝印标明方向和电压。

## 17. 第二版优先修正项

最高优先级：

1. 确认右后轮编码器不要落在 `encoder_quad_init()` 不支持的 TIM5 风险上。
2. 三路驱动补齐 EN/nSLEEP、nFAULT、电流采样。
3. 急停输入必须明确。
4. VBAT 采样必须明确。
5. IMU 远离无线和大电流，固定方式明确。
6. SPI3 绝对值编码器引脚和 CS 保持和代码一致。

这些比增加复杂外设更重要。没有安全和反馈，闭环代码很难可靠调出来。
