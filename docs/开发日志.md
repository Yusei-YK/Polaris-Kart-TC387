### 2026-07-22 蜂鸣器时序问题完全解决

**最终方案**：CCU60_CH1独立1ms中断 + GPIO软件翻转

**技术细节**：
- 放弃PWM方案，改用GPIO软件翻转生成方波
- 新增`kart_horn_isr()`在1ms中断中推进节拍机
- 新增`horn_set_freq()`设置目标频率，`horn_gpio_tick()`按周期翻转GPIO
- 警报双频：300Hz/900Hz交替，连续10秒（10次1秒切换）
- 节拍表单位改为1ms（与中断周期匹配）

**实测结果**：
- ✅ 鸣笛1秒：实测1.00s（误差<10ms）
- ✅ 鸣笛2声、3声、4声：节奏准确
- ✅ 急促鸣笛：0.5s间隔×7次
- ✅ 警报鸣笛：连续10秒，300Hz/900Hz明显交替

**根本原因分析**：
- 主循环周期不可靠：IPS200刷新耗时≈36ms，实际周期41ms（设计值5ms）
- PWM重初始化开销：`pwm_init()`内部调用`start()`重启GTM ATOM，产生silence gap
- 节拍累加以循环次数计数：200次×41ms ≈ 8.2秒（实测8.28秒）

**核心经验**：
- 精确时序任务必须用硬件定时器中断，不依赖主循环周期
- GPIO软件翻转优于硬件PWM（对于频繁切换场景）
- 节拍表单位与中断周期匹配（1ms中断 → 节拍表单位1ms）

**技术文档**：`docs/horn_timing_issue_resolution.md`（3290字，完整记录问题、分析、方案）

### 2026-07-06 TopSpeed 转向闭环结论

- 【已解决】TopSpeed 的转向闭环不能直接搬到卡丁。
- TopSpeed 用舵机，PWM 直接控制角度，没有前轮角度传感器闭环。
- 卡丁当前硬件是直流转向电机 + 绝对编码器，必须自己写前轮角度环。
- 可复用的只有 PID 算子和控制结构思想。
- TopSpeed 的 `angle_ctrler` 控的是车身航向 IMU yaw，不是前轮角度。

### 2026-07-20 Flash 路径存储层落地（P0，纯软件）

**mission 仲裁回顾（用户遗忘，重讲）**
- 所有模式（IDLE/SUBJECT_1/SUBJECT_2/REMOTE/FAULT）只能经 `kart_mission_set_mode()` 切换，内部固定 `mission_stop_all()`(exit) → `mission_enter()`(new)。
- `mission_stop_all()` 是"残留输出归零"总闸：停 record/playback、后轮清零关速度环、关航向外环+转向内环、蜂鸣器静音、清空语音队列。这保证任意模式切换不残留动作。
- **副作用**：进 REMOTE 时 stop_all 会 `kart_record_stop()`，故"遥控驾驶同时录制"当前做不到。解决方向（Flash 之后做）：把录制降级为"与模式正交的副状态"，REMOTE 中可独立开录制标志，stop_all 不无条件切录制——对应用户"复刻遥控路线"需求。

**新建 `kart_flash.c/.h`（DFlash 槽位持久化）**
- 存储流布局（uint32 为单元顺序铺开在槽位连续页）：`[MAGIC, count, 点0(x/y/yaw/vL/vR 各1word), 点1, ...]`。float 按位存为 uint32（`flash_data_union` 互转）。
- 槽位规划：8 槽 × 6 页/槽 = 48 页 < 128（DFlash 总页）。单槽容量 `(6*512-2)/5 ≈ 614` 点 > 500 上限，够用。`KART_FLASH_MAGIC='KPTH'` 读回校验，magic 不符判空槽。
- 接口：`kart_flash_save_path(slot, wp, count)`（阻塞擦写，只写用到的页）/`kart_flash_load_path(slot, wp_out, max)`（读页头 count 为准，支持跨页）/`kart_flash_slot_count(slot)`（只读页头，供菜单显示槽位是否已录）。
- **纪律**：`flash_write_page` 是逐字阻塞擦写（耗数 ms），只能停车静止时调 save；load 是纯读地址映射，快，可在准备阶段调。

**`kart_record` 加 Flash 便捷接口**
- `kart_record_save_to_flash(slot)`：录制进行中拒存（返回3）、空返回2，否则存 record_buf。
- `kart_record_load_from_flash(slot)`：读回覆盖 record_buf 并置 record_count，供 kart_playback 直接复现。

**VOFA 研发命令（不占正式流程，比赛现场走菜单）**
- `w<slot>`：存当前 RAM 路径到 Flash 槽位（仅速度环关闭时执行）。
- `f<slot>`：从 Flash 槽位读回 RAM（看 ch19 录制点数验证读回成功）。

**下一步实测（P0 验收）**
- ADS build（kart_flash 新文件需确认进 subdir.mk）。
- 录一遍(r1→手推/遥控→r0) → `w0` 存 → 断电 → 上电 `f0` 读回(ch19 点数应等于录制点数) → 摆回起点 z 清零 → `b1` 复现，量终点偏差 → 决定是否需要多遍拟合。

### 2026-07-20 遥控+录制共存确认 + 复刻期间遥控急停钩子

**共存结论（无需改代码）**
- `kart_record_poll()` 在主循环无条件每拍调，只受 `record_running` 门控，数据源是 5ms 中断更新的 odom，与驱动源（遥控/复刻/科目一）无关。故遥控驾驶同时录制天然可行。
- 正确操作序列：`m3`(进遥控) → `r1`(开录) → 遥控驾驶 → `r0`(停录) → `w<slot>`(存 Flash)。
- 唯一限制：必须先进 REMOTE 再 `r1`。反之 `r1` 后再 `m3` 会被 `mission_stop_all()` 停掉录制（切模式统一停机）。
- 修正此前臆测：曾误判"共存做不到需重构"，实际细看调用链后确认无需改代码。

**复刻工作流答疑（回复用户 4 问）**
- 复刻启动：VOFA `b1`（或科目一 START 键）；前提 `record_count>=2`、已 `z` 清零 odom、车摆回起点。
- 录完回原点：`r0` 停录后路径已固定在 RAM，遥控开回或手推都不破坏数据（别误触 `r1` 重录）。
- 航向起点校准：**无**。`kart_playback` 仅平移不做旋转补偿，起点朝向须手动对齐 IMU yaw，偏差越小越准。

**复刻期间遥控急停钩子（kart_mission.c，已落地）**
- 需求：复刻期间保留遥控急停，但油门/转向信号不得干扰复刻。
- 现状：复刻走 `MISSION_SUBJECT_1`，`kart_remote_control_update()` 只在 `MISSION_REMOTE` 调用，故复刻期间遥控原本零作用（既无急停也无干扰）。
- 实现：`subject1_loop()` 顶部加 `subject1_estop_requested()`，仅在有动力输出的 `S1_CONE_ROUTE`/`S1_REVERSE_IN` 两阶段生效；命中即 `kart_mission_set_mode(MISSION_IDLE)` 完整停机。
- 判据只读"遥控失联 或 三段拨低挡"，**不读油门/方向通道**，天然满足"急停保留、油门转向不干扰"。
- deadman 语义：把遥控当安全绳，失联=急停。故复刻/倒库期间遥控须保持开机且三段不在低挡，否则立即停车回 IDLE。`S1_WAIT_START` 不挂钩，避免默认低挡进模式即误触。

### 2026-07-21 修复遥控挡位冻结导致 IDLE 下 b1 必失败

**现象**：`m0` 后 VOFA 遥控数据冻结（ch28 在线态/ch33 挡位不随遥控实际状态变化），`b1` 复现必失败（ch0=0 车不动）；偶发"录完直接 b1 能复现"但不稳定。

**根因**：三段挡位 `remote_sw3` 只在 `kart_remote_control_update()` 里解码（kart_remote.c:291），该函数只在 `MISSION_REMOTE` 模式下被调用。故 **IDLE/科目一/科目二模式下 `remote_sw3` 冻结在上一次值**（上电默认 `KART_REMOTE_SW3_L`）。
- VOFA `ch33`（挡位）读 `remote_sw3` → 冻结不变。
- `kart_playback_poll()` 的 deadman 判据 `kart_remote_get_sw3() == KART_REMOTE_SW3_L` → **m0 下恒成立** → 每拍立即 `kart_playback_stop()` → ch0=0。
- "偶发能复现"原因：刚从 `m3` 中/高挡切出时 `remote_sw3` 冻结在 M/H，此时 `b1` 能跑；但下次上电或经过 `m0` 后 `remote_sw3` 又变回默认 L。

**修复**（kart_remote.c，3 处）：
1. 把 `remote_sw3` 静态变量和 `remote_decode_sw3()` 前置声明移到文件作用域顶部（失联计时段落之后）。
2. `kart_remote_poll()` 末尾加挡位解码：在线时每拍调 `remote_decode_sw3()`，失联时钳到 L。**全模式实时**，不再依赖遥控模式。
3. `kart_remote_control_update()` 删掉重复的 `sw3_raw` 读取和 `remote_decode_sw3()` 调用，改为直接读全局 `remote_sw3`。

**验证点**：
- `m0` 下拨遥控三段，VOFA `ch33` 应实时 0/1/2 跟随。
- `m0` → 摆正车 → `z` → 遥控开机推中/高挡（ch33=1 或 2）→ `b1` → 车应正常复现（ch0 跟随录制速度，不再恒 0）。
- 遥控关机或拨低挡（ch33→0）时 playback 应立即停车（deadman 生效）。
